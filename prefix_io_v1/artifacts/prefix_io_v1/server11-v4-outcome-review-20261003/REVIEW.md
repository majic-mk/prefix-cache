# V4 GPU 结果独立复算

结论：这轮真实跑通了有限条件下的原生生命周期和调度验证，**没有验证策略净收益**。开启策略的 on 比 off 慢 **7.27872%**，比 shadow 慢 **7.36844%**；on 的成本覆盖失败应保留为负结果。

仅使用下载的 `V4_FINAL_EVIDENCE.json` 与此前 `SERVER11_FINAL_EVIDENCE.json`。本次只做本地 CPU 复算，没有 GPU/RPC。各输入的实际 SHA 和可复现计算代码见 `REVIEW.json`。

128 个事件区间按前 16 步、选中一步、后 111 步完整分区。数组长度、分区求和、已存汇总、完整 token 一致性、共同源码/校准引用与 GPU 账本求和核对通过。请求至排空结束与完整请求的差额包含中间记录开销，不能把它全部称为 drain；真正 drain 函数时间为 off 0.673695 ms、shadow 0.736107 ms、on 2.283091 ms。

on 的受控步是最大峰值；其第 18、19 步另有 25.109344、22.971807 ms，第 77 步另有 22.646112 ms。on-off 事件区间总差为 109.233283 ms：前 16 步累计 +3.694592 ms，受控步 +52.917571 ms，后 111 步累计 +52.621120 ms。因此差异没有只局限于受控一步。这里是按步骤对齐的描述性差值，不能直接把所有后续峰值归因于调度。

有限资格与成本覆盖是两个不同指标。三臂都记录了 128 tokens 完整输出、128 帧、单次 917,504 bytes 原生 SSD 读取完成及原 shutdown/会话排空。shadow 提出延期但不阻塞；on 的 181 次阻塞从首次至末次跨越 64.898699 ms，随后原生读取实际被接收。这支持实现与生命周期可行。

但 on 的受控步 **68.464035 ms** 超过冻结成本上界 **18.865088 ms**，超出 **49.598947 ms**。因此 `limited qualification = true` 与 `cost migration = false` 没有矛盾；前者不能改写为性能验证通过。证据明确将 GPU 不重叠、资源释放信用、production 与 strategy effect 保持 false。

与 V3 对应三臂相比，V4 请求至排空结束分别下降 25.82942%、29.04638%、25.72952%；off/shadow 本轮前后步均值也基本平坦。这与共同路径改进方向一致，**不能计为研究策略收益**。on 对同轮 off 的惩罚由 V3 的 7.13443% 变为 V4 的 7.27872%，未消除。V3 汇总没有逐步数组，本报告不编造旧分段均值。

这些是单次、固定顺序、单 workload/单文件条件的描述结果，不能证明统计显著提升、全 P4/P5 完成、正式 SLO 或广泛工作负载泛化。事件区间也不等于纯 kernel 时间；仅凭这两份 JSON 无法把剩余额外耗时精确分成重试观测、CPU 提交间隙和 SSD 干扰。

本轮四个 guard 记录均成功退出并排空；独立求和为 **1,021.929462 秒**。累计 **22,380.561258 秒**，剩余 **6,419.438742 秒**，活动 reservation 为空，累计加剩余仍为原 28,800 秒。下一步应归档这份有限成功、性能负结果；不提高阈值、不伪造释放信用、不重复无变化的 GPU 试跑。
