## 3. 先统一四个容易混淆的概念

### 3.1 目标全重算，不是整请求 dense

`TARGET_FULL_RECOMPUTE(C)`：C 的全部 token 从输入到最后一个 block 连续执行所需 QKV、attention、输出投影、MLP/残差等操作；没有用 C 的历史 KV 替代某一层中的目标位置。上游可以采用近似工作状态。

`EXACT_REQUEST_REPLAY`：对原请求输入进行能够证明精确的全量重放，或从经过验证的精确检查点恢复；其结果可与相同数学配置的 dense 对照。

`SELECTIVE_REPAIR(C)`：只重算 C 的一部分位置，其余位置复用。这个混合工作张量不得以“全片段重算”名义发布。

`EXACT_PREFIX_HIT`：复用与当前完整前缀、位置和模型兼容的精确原生 Prefix Cache。没有本次重算也可以保持精确，但必须有已验证证明链。混合来源不能进入精确 Prefix Cache。

### 3.2 r=1 以执行账本判断，不按函数名判断

即使入口名为 repair，只要 C 在所有层的所有 token 实际连续完整计算，它可以符合 TARGET_FULL_RECOMPUTE。若之前有 token 已经退出计算，后面把 r 改成 1 不会补回缺失层，不能入库；需要额外重放则明示并计费，默认不为物化主动重放。

### 3.3 Source 是内容状态对象，不是“精确”的同义词

旧 `canonical_source`/`DENSE_EXACT` 只保留原意。v2 使用 `SourceArtifact` 统称允许的两类对象；混合对象不能伪造旧 exact 标志。

### 3.4 只有因果前文影响目标，后文不影响

保存 C3 不要求 C4…C10 精确。后面的用户问题变化可以改变修复关注度，但不自动改变 C3 的 KV。计算依赖范围必须依据原始绝对位置，不使用整个请求一个混合 flag 覆盖所有 Source。

## 4. 来源类型与传播上限：必须能由执行过程计算

### 4.1 类型

| 类型 | 证明要求 | 入库策略 |
|---|---|---|
| `EXACT_CONTEXT` | 目标全重算；目标的因果依赖均有精确证明；G=0 | EXACT_ONLY 与 ALLOW_MIXED_G1 都可接受 |
| `MIXED_CONTEXT_FULL_SEGMENT` | 目标全重算；依赖有已知近似来源；G≥1 | 主候选仅接受 G=1 |
| `UNKNOWN_PROVENANCE` | 依赖缺失、类型不明、trace 不能证明 | 禁止新发布；不自动按精确或第一代处理 |
| `PARTIALLY_REPAIRED_WORKING_KV` | 目标至少一层至少一个 token 用了旧值 | 只作请求工作状态，不发布为上述完整片段 Source |

G 是保守的近似复用链深度上界，不是误差大小或安全等级。“G=1”不表示质量必然好。

### 4.2 可实现的传播规则

为输入 hidden、residual、工作 KV 的相关因果范围记录 `dependency_rank`（非负整数或 UNKNOWN）。

1. 已验证精确输入/精确 Prefix 引入 rank=0。
2. 将保存的 Source S 用于新的非精确匹配上下文，旧 KV 被近似复用时，注入贡献 `G(S)+1`。即使 S 在其出生请求中是精确的，这次跨上下文使用也不是精确 Prefix hit。
3. 本请求内正常完整计算、残差传播、不同 token/Segment 之间的因果 attention，只取合法输入 rank 的最大值，不凭空再加 1。
4. 目标全重算得到的 Source，G 为其全部相关层状态的依赖 rank 上界。新发布动作本身不再额外加 1。
5. 依赖中有 UNKNOWN 则禁止发布。上游粗粒度追踪可以保守高估，不能低估；后方不可见 Segment 不参与。
6. 遗漏/删除父 Artifact 后，已验证 G 与元数据仍然有效。它们是来源记录，不要求父 KV 永久存活。

**例子：**旧精确 S0(G=0) 跨上下文复用 → 当前 A 的工作状态 rank=1 → B 全重算得到 M1(G=1) → 同一请求 C 读取 B 后全重算仍为 G=1，而不是 G=2。下一请求将 M1 跨上下文复用会注入 rank=2，后续全重算候选 G=2，主池拒绝保存。

禁止只检查直接前一段的 Source 标签。中间经过一个全重算 Segment 不能把传播历史清零；也不能每经过一个 Segment 或 Transformer 层都加一。

### 4.3 生成限制与运行时使用分开

主池可以使用 G=1 Source 进行近似复用，但这可能使本请求后续新候选达到 G=2，后续候选不入库。这不意味着必须重算前九段来强制生成 G=1。

主实验始终只存 G≤1。需要测 G=2 风险时在独立命名空间/in-memory 诊断中执行，禁止修改主池代数上限来运行。

### 4.4 正确性参照也必须分开

- 混合上游固定不变，只对目标完整重算：比较 native 执行与直接显式拼接该混合上游的参考，验证实现正确。
- 同一原始请求整请求 dense：评价混合上下文带来的真实质量变化。
- 不能要求前一个结果逐位等于后一个结果；二者不同并不自动表示实现 bug，也不能据此忽略质量损失。

## 5. 存储设计：每个 Source 仅拥有目标片段

### 5.1 需要持久保存

1. C 自己的每层 pre-RoPE K 与 V，或经过验证的等价格式。
2. 独立、可小范围读取的候选 SelectionState。默认只含选定浅层 K；若是额外复制，字节必须计入。
3. 有界 metadata：内容/模型/权限身份、原始起止位置、类型、G、完整目标计算证明摘要、Artifact digest、出生请求和共享 manifest 引用。

不保存历史前文 KV、不保存完整 attention、不保存主请求全部 hidden state，不把切片 view 的父存储意外保留下来。

### 5.2 来源记录的三层结构

`Source metadata` → `request execution manifest` → 已有的输入数据/受控日志。

共享 manifest 每个出生请求存一份，按顺序记录 chunk 身份、各自实际 Source ID、执行策略、repair mask 摘要和必要代数证据。C10 的 metadata 只存 `manifest_id + target_occurrence/prefix_end` 等引用，不再复制前九段的清单或原文。

Manifest 中的 Source 引用是非拥有型引用，不持有父 KV lease，不阻止父 Artifact 被 LRU 回收。运行时审计保留足够摘要；原始实验复现可使用单独、有界的输入与执行快照。

只有 hash 不能重建原文。实验输入/原始 token 或可重建的不可变数据集配方保留在共享受控工件中；运行时不要为每个 Source 重复存一遍完整 prompt。

### 5.3 Prefix shadow 完全解耦

当前 [C1] 的目标导出还调用 [C2] 的整请求 shadow publication，v2 要拆开：

- `capture_source_segment`：只抓目标片段，不调用 shadow publish。
- `publish_exact_prefix_shadow`：可选原生 Prefix 功能，自有预算和独立触发；仅接收已验证精确前缀。
- Source 收集默认不创建 shadow。缺 shadow 的实验应显式关闭对应 Prefix 功能，不能删除 shadow 后仍声称原生 Prefix 已验证。
- 主方法和基线使用同样的 Prefix 开关；另一个 Prefix-on 对照单独重资格。

### 5.4 空间和权限

一份标准 Source 主体：`2 * layers * target_tokens * kv_heads * head_dim * dtype_bytes`。与该片段排在第几位无直接乘数关系。

必须区分：持久 Artifact、SelectionState、共享 manifest、原生 Prefix 缓存/shadow、工作 KV、暂存、A/B 参考、模型权重。物理共享缓冲只算一次，同时报告逻辑量和物理峰值，不能因“逻辑一份”漏算副本。

所有对象绑定同一授权域及相关文档版本。历史前文权限必须覆盖，不只检查目标文本。默认单授权域，未知或撤销权限禁止复用；本轮不开发新的跨租户共享机制。

## 6. 在线执行顺序与混合 Source 的真实产生

### 6.1 一个请求的时序

```text
请求到达 → 固定可见 Source 快照、原始 token 与位置
    ↓
内容 miss 的片段预先标为 TARGET_FULL_RECOMPUTE，预留可能 capture 的早层切片
    ↓
正常执行共同早层（初始 d=2）；在线观察只能读取本次实际状态
    ↓
每个命中片段只比较候选浅层 K；确定 winner 并 freeze
    ↓
同一 checkpoint 的 Q×当前K 重要性共享一次
    ↓
读取 winner 必要的 V，联合偏差生成 mask
    ↓
请求级资源/成本准入；未准入的目标保持全量活跃，其余可近似复用
    ↓
后续层：复用片段只算 repair；全量片段始终计算其全部 token
    ↓
目标全量计算中抓取本目标逐层 KV，传播真实来源 rank
    ↓
prefill 完成：完整性/类型/G/去重/预算/池快照检查
    ↓
原子发布为未来请求可见的 Source；当前请求不可读自己新发布的版本
```

前九段可以近似、C10 全量。C10 的生成不触发前九段全量重放。若整请求质量策略在首次近似提交前决定全量，则是另一个明确动作。

### 6.2 三条回退路径命名

| 路径 | 含义 | 可宣称精确？ |
|---|---|---|
| `TARGET_FULL_CONTINUE` | 决策边界前目标一直全算；其后继续全部算，上游可近似 | 仅根据实际依赖分类 |
| `PRECOMMIT_EXACT_CONTINUE` | 尚未近似提交，全部请求从已证明精确的 live 状态继续 | 可验证整请求精确 |
| `EXACT_REQUEST_REPLAY` | 已近似传播，需要丢弃受影响工作状态后精确重放 | 明示额外成本；不能称免费继续 |

纯设备故障、OOM、取消不是普通质量回退：先 fence/清理、记录失败。无法证明状态可恢复时，不拿残留状态继续下一请求。

### 6.3 capture 不能事后凭空开始

miss 片段在开始计算前预约；完整不匹配在 d2 才发现时，必须能从尚未释放/覆盖的当前工作缓存或预留 pre-RoPE 切片恢复早层 KV。不能只保存第3层以后却标为全层。

对每层，attention-ready 后目标 KV 可能还供当前 query 使用；异步导出必须先复制到有界独立缓冲或保持读 lease，等事件完成再释放。Source 持有独立切片，不持有全请求 Tensor view。

若早层无法恢复、容量不够或 export 超预算，正常回答仍继续，只放弃本次物化。禁止偷偷调用第二次 capture forward 补齐。诊断参照若额外运行 dense，单列在诊断成本，绝不发布回生产池。

## 7. Source 排名和联合 repair 定义

### 7.1 选择器不加入 Query

沿用 `K_trim_legacy` 并完整记录原函数 hash；另测 `K_mean`：

\[
D_s=\frac1N\sum_j\frac{\|K_j^{cur}-K_j^s\|_2}{\max(\|K_j^{cur}\|_2,\epsilon)}.
\]

不对每个候选整体任意归一化成相同范围。K+V 排名只在后续独立消融，额外 V 读取入账。

新来源策略有独立身份过滤与阈值 Profile。排序仍只用 K/KV，来源类型/G 可以用于允许范围和确定性同分 tie-break，不加入用户问题相似度。旧 tie-break 不改；新系列精确同分可优先 G=0，再按出生次序、ID，规则在实验前冻结。

Original trimmed score 忽略最大的 rho 部分偏差，不等于新 repair 的真实剩余误差。rho 与实际 r 分开记录。使用新 repair、混合来源或新边界都要重新验证对应阈值。

### 7.2 观察层

`completed_depth=d` → 观察 layer d+1 的投影。d=2 对应 block3 Q/K/V；若要研究“前两个 block 内的 Q”要用独立 named policy，不混用。

主实验先共同早层全量计算到 d2，后续不同片段才走不同模式。这样当前观察包具有明确来源；并不让未来 mixed Source 的深层误差因此被提前看见。

### 7.3 Query 重要性

真实问题 span 由 builder 和 tokenizer 确定；不根据答案或支持句选 Query。最多16行，固定等距覆盖首尾。缺可靠 span 则 D-only 回退并记录；不猜位置。

对同一层：

\[
a_{h,i,j}=\mathrm{softmax}_{t\in\mathcal V_i}
\left(\widehat Q_{h,i}\widehat K_{g(h),t}^{cur\top}/\sqrt{d_h}\right)_j,
\qquad S_j=\operatorname{Mean}_{h,i}a_{h,i,j}.
\]

按当前绝对位置、真实 GQA、因果 mask、滑窗和模型 logit 变换计算。完整合法可见上下文提供 softmax 分母；只在目标 Segment 内做 softmax 是另一个局部消融，不是同一算法。

同一请求同一检查点共享一次全请求评分，不为每个候选或每个 Segment 重复做 QK。分块计算，不把全部 attention 矩阵搬到 CPU。

### 7.4 winner 偏差与乘积

新系列参考定义（不静默改变 legacy）：

\[
d^X_{g,j}=\frac{\|X^{cur}_{g,j}-X^{win}_{g,j}\|_2}
{\max(\|X^{cur}_{g,j}\|_2,10^{-6})},\ X\in\{K,V\},
\qquad D_j=\operatorname{Mean}_g(0.5d^K_{g,j}+0.5d^V_{g,j}).
\]

在目标 eligible 集 E 上：

\[
\bar S_j=S_j/\max(\operatorname{Mean}_E S,10^{-12}),\quad
\bar D_j=D_j/\max(\operatorname{Mean}_E D,10^{-12}),\quad
R_j=\bar S_j\bar D_j.
\]

执行 `Top-ceil(0.15*|E|)`，最终只生成一份 token mask。并列按绝对位置稳定排序。先分别归一化的正全局尺度不改变纯乘积在同一 Segment 内的排序，但影响平滑/阈值解释；不能夸大它本身的贡献。

关注量为零/全部不可见则用同系列 D-only。极小但有限关注量不能事后任意判无效；阈值如非数值零必须单独开发冻结。偏差全零时 fixed15 仍使用稳定数量，不据一次浅层结果跳过全部 repair。NaN/Inf 统一拒绝评分/入库，不将其解释为高风险新模式。

winner 的必要层 V 是额外数据依赖；不能为了它等待所有深层。当前 QKV 已投影不代表评分、状态保留、读取和 Top-K 免费。

### 7.5 后续优化的边界

仅 Q×D 有价值后，分别测一个 lambda=0.5 的平滑版本，以及“同一 KV head 先与相应 Query heads 的关注度相乘再汇总”的 headpaired 版本。单次只增加一项，不开 alpha×lambda×depth×head×ratio 全网格。

实际 mask 外残差与 trim overlap 初期只记诊断，不自动加第二个安全 Gate，也不冻后换 Source。

### 7.6 一个新加入的风险：浅层签名碰撞

同一历史 prompt 用两种后续上游执行策略生成精确/混合 Source，如果近似只在 d2 后生效，它们的 d2 SelectionState 可能相同，深层却不同。浅层选择器无法凭同一个观测区分所有这种情形。

必须设置同 prompt、不同上游执行配方的配对试验，测浅层碰撞率、深层差异、真实 QA；来源身份包含 execution manifest，不能仅用 prefix token hash 合并。精确 digest 相同可去重；只有浅层近似就删除另一版本，默认不开启。不能声称来源标签或 G=1 消除了这个可辨识性问题。

## 8. Source 新增与淘汰规则

### 8.1 主规则

```
触发：真实内容 miss，或完整可比较池的最佳 Source 超过新增阈值
AND 目标本次所有 token/所有层连续完整计算
AND 相关来源已知，类型符合当前策略，G≤当前上限
AND 新对象非重复且有完整层/位置/数值证据
AND capture、写入、临时空间和全局/每内容容量允许
AND 来源清单/Artifact/SelectionState 验证完毕，可原子发布
```

首次 Source 也允许是已验证的一代 mixed，不要求池必须先存在一份本内容的 exact。它的上游近似应来自真实的其他已存在 Source；全空池第一请求自然是全量。

后续新增需要完整 candidate-scope 证据；已有逻辑对象暂时不在 GPU、载入失败或因来源策略被过滤，不等于首次文本没见过。记录 stored/eligible/compared/available 四种计数，不用其一替代其他。未知或缺失选择状态默认不宣称全池不匹配。为避免筛掉某类Source后误称全池已查，v2主增长模式只在stored=eligible=compared且范围完整时以mismatch新增；被过滤或不可比较对象仍在池内时，记录范围不足并跳过此次增长。

### 8.2 选择阈值与新增阈值

同一分数定义和尺度下允许 tau_add≥tau_reuse；第一版相等，双阈值后续消融。两者绑定 model/depth/repair/provenance-policy/runtime。v2初版同一激活策略内所有允许的G0/G1候选共用一组阈值，质量按来源分别报告；将来若分类型设置阈值，必须逐候选检查“全部未通过”，不能用全池最小分数与某一个类型阈值比较来推导全池不匹配。

全池都超阈值只表示未通过代理规则，不等于数学证明全部无法正确回答。混合来源策略未冻结质量 Profile 前，仅限隔离诊断，不能使用 exact-only Profile 宣称线上安全。

目标被 FULL_CONTINUE 后可能产生 M1 而不是 exact：记录真实来源，不为满足原 enum 重跑前文。不兼容触发与候选入库资格是两道判断，前者发生不保证后者成功。

### 8.3 不自动触发增长

运行故障、纯成本拒绝、只比较部分候选、候选 margin 不足、末尾问题变化、标准答案显示错误、某次得分最低，均不单独触发。质量标准答案只属于离线评价，不在线使用。

其他原因本来产生完整目标结果的机会式增长、主动探索收集，保留为后续独立策略，默认关闭。

### 8.4 物化生命周期

`PROPOSED → CAPTURE_RESERVED → CAPTURING → COMPLETE → VALIDATED → PUBLISHED_PROBATION → ORDINARY → EVICTED`。

任何失败都不发布半成品。Source 出生的当前请求使用预先冻结快照，不读本请求的新 Source；初期只在请求完成后入池，下一请求才可见。未来并发需保留真实可见 epoch。

同内容满池按原保护式实际使用 LRU（以实际请求绑定/使用记录为准，不因仅参与比较刷新）；锁定、拷贝/执行或有限 probation 对象不可删。无合法 victim 则放弃。本轮不引入学习式淘汰。两个来源策略容量都为同一个上限4，而不是 exact4+mixed4。

### 8.5 必报供给链

逐级统计：miss/全池不匹配 → 目标全量机会 → 精确/M1/M2/未知候选 → capture成功 → 去重 → 发布 → 后续入选 → 真正复用 → 无用淘汰。增加的创建率不能单独记作性能收益。

## 9. 数据与几何：保留旧分区，新场景独立登记

1. 旧90-case与已观测pilot不变，只作回归/探索。新机制样本来自[C4]未使用内容组，先核对原始官方文件、完整 token 身份、支持句范围、来源差异及交叉污染。

4. 原顺序没有真实时间戳就标 `corpus_pseudotime`。不把自然文档重复与真实用户时间序列混为一谈。
5. 首批机制最多30目标、每组最多10、稳定种子20260918。不足如实报告，不修改原最小组数/目标数。
6. **10个512-token Segment至少5120个token，超过旧4096总输入限制。** 旧P1保留4096契约；真实10段场景建立新的8192或足够长度的配置、模型资格与清单。不能仍写4096，也不能删段凑长度。CPU/小GPU正确性可用短合成10段，但标 synthetic_correctness，不当真实RAG收益。
7. 新mixed历史来源必须在原真实prompt上按冻结上游策略实际执行；不可离线随意拼一个未发生过的前文KV并宣称自然Source。配对诊断可做受控上游替换，单独标 controlled_provenance_diagnostic，不能混入自然系统收益。
8. Source E/M配对对象、其父来源以及后续消费请求不能穿过fit/validation分组边界。诊断额外dense仅评测使用，不进入任何在线缓存池。

旧短答案32-token、short_answer_v1、F1相对dense容忍0.02等照原清单核对。新数据不能根据输出反复修提示或提取规则。

## 10. 实验阶段与依赖

| 阶段 | 核心问题 | 进入条件 |
|---|---|---|
| P0 | 代码、来源追踪、切片存储、数据与数值是否正确 | 可以先做CPU；GPU需授权和preflight |
| P1-E | 精确历史版本是否存在互补空间 | P0-E正确性和原队列资格 |
| P1-M | 一代混合来源能否正确收集，是否带来不可接受退化/签名碰撞 | P0-M正确性；无需假装旧exact资格自动覆盖 |
| P2 | 固定Source下Q×D是否有独立作用 | 对应类型有可用合法对象；至少有继续机制理由 |
| P3 | 同池同repair下当前K选择能否胜过CFO/强单Source | H1或预登记救援出现空间，P2选择固定 |
| P4 | 真正d2复用与多Segment联合质量/TTFT | 机制有增量，当前策略Profile和数值资格 |
| P5 | 放宽来源在真实序列中是否提高生命周期净收益 | P1-M与P4通过；独立池同字节 |
| P6 | 独立两模型与原生近邻对照 | 前述关键机制/系统条件满足 |

P1-E失败不自动证明mixed池无价值；必须完成已登记的P1-M再整体判定。P1-M失败可以暂停mixed上线，保留exact分支并如实报告，这不允许把最终系统说成已支持有效mixed。两种来源都没有空间时停止多Source扩展，不重新命名或无限调参。

### P0：逻辑、存储与正确性

首批文件：`baseline_audit.md`、`v2_change_map.md`、`source_provenance_contract.json`、`input_qualification.jsonl`、`cohort_manifest.json`、`planned_actions.csv`、`cpu_tests.log`、`correctness_report.json`、`gpu_preflight.json`。

必须覆盖附录测试矩阵，尤其：前九段approx+第十段full可产M1；同请求传播不递增；间接M2不能洗白；后文不改变前段标签；slice view不留全请求；关闭shadow不影响目标capture；旧exact入口仍拒绝mixed；未知代数/NaN失败封闭。

P0可做不改变研究评分的来源/storage最小实现。新增Q×D算法放P2，不能先把所有旧基线改掉。代码已经正确且有匹配hash证据的不重写。

### P1-E：继承旧机制诊断

固定旧legacy normalized K/V repair=15%、共同 first reuse layer=9、prompt与decoder。每目标执行dense、四个历史精确Source、独立S0，最多`6N≤180`个主要目标动作，来源构建/自状态检查另列。

计算earliest/latest、CFO、d1/d2/legacy排名对应的真实QA。动作结果仅在实际Source、mask、boundary、输入、模型与执行代码全部匹配时复用。选择器运行时成本不能由结果回放填成0。

QA互补空间：

\[
H_g=\frac1{|Q_g|}\sum_q\max_s F(q,s)-\max_s\frac1{|Q_g|}\sum_q F(q,s).
\]

post-hoc best-fixed与per-request oracle都是诊断上界，不是在线策略。必须另外报告可部署earliest/latest、S0和fit-only规则。

本任务的预登记筛查目标：至少两个隔离组出现互补，macro H≥0.01，或相对同一池best-fixed的合格覆盖空间≥0.05。只有两组属于探索证据，不能认证泛化。

### P1-M：本轮新增的强制配对来源实验

在看新输出前选定至多12个消费目标；历史出生请求与消费请求分开。

对同一个出生请求、同一目标内容C准备：

- `E(C)`：整请求或相关依赖精确的全量参照所产生的目标Source。
- `M1(C)`：出生请求中前文按冻结策略近似复用已有G=0 Source，C所有token/层全算；capture仅保存C。

E/M1必须有相同原始目标token、同模型、同位置语义。它们是受控配对来源，不宣称两次都是同一条自然线上运行；额外E参照成本计入实验预算。

在每个未来目标中分别执行`dense / E / M1`，消费端上游策略保持相同，repair和边界保持相同。最多36个主要消费动作；每个唯一出生对象的额外构造必须预列数量及时间，禁止无限补Source。

**四项结果：**

1. 在固定混合前文下，目标完整计算与显式混合参考一致（实现）。
2. 相对整请求dense、相对E来源的F1/EM与有害退化（质量）。
3. d1/d2 Source签名是否相同或近似，而深层/输出已经不同（可辨识性）。
4. 只保存C后是否可在父KV释放情况下加载复用（存储独立性）。

先报告配对每例及macro-group均值。预登记mixed相对E的mean F1非劣容忍0.01作为候选目标；小pilot不足以给可靠单侧区间时为INCONCLUSIVE，不宣称安全。类型标签和一代上限不能替代质量检验。

另在隔离命名空间做最多6个代数/传播正确性情形；G=2只能作可选风险诊断，不发布主池。是否添加模型G=2质量动作、具体数量须在第一次新结果前写入manifest，否则本轮不自动启动。

### P1-R：一次有界救援，不能无限寻找正例

P1-E原repair无空间或混合配对差异提示mask可能关键时，可执行预登记的Q×D_15救援：同一已冻结池与边界，至多12个目标，每个dense+最多4历史+S0，即最多72个消费动作。它需要先通过P2的数值实现检查，但不要求已有P2质量成功。

救援最多一次，不改样本、权重或比例去追正结果。P1-E/P1-M/P1-R仍无互补空间，则停止复杂多Source阶段。机制有效但mixed质量不合格，则明确仅exact分支继续，不能不报告新设定失败。

### P2：固定Source，隔离repair贡献

预先固定earliest或其他不使用答案的Source规则。先exact队列，再matched M1队列，分别报告来源类型。

比较Legacy、同一新定义下的D-only、Q-only、Q×D。D/Q/QD三个纯公式对照必须同producer、consumer、固定支持集合与15%数量。Legacy若层级刷新不同，只作整策略对照。

同一目标、同一winner，比较headpaired或smooth时一次加一个。初版最多30目标×4主arms=120消费动作（来源/dense补充另列）。观察mask重合、源分数碰撞、残余差异、实际token-layer和成本。

Q×D若被D或Q的质量—成本曲线稳定支配，不默认开启。Source选择研究是否继续单独判定，不把局部失败隐藏。

### P3：选择器×repair交叉消融

| Arm | 选择器 | repair |
|---|---|---|
| A | CFO | Legacy |
| B | 当前K_trim | Legacy |
| C | CFO | Q×D |
| D | 当前K_trim | Q×D |
| E | 预声明强单Source | Q×D |
| F | 独立S0 | Q×D |

在D附近加K_mean，必要时KV_mean；来源队列先固定可见池，再比较EXACT_ONLY和ALLOW_MIXED_G1。不能一边更换候选池、一边更换选择器，却把总差值都叫选择器收益。

CFO元数据须正确采集/复现。mixed候选的元数据必须来自其实际出生执行，不借用exact同prompt的CFO。原生Cache-Craft与统一池上的CFO适配分开命名。无法合法取得mixed-CFO时，该格标NOT_EVALUATED并报告比较缺口，不能把缺失基线当作失败。

B-A检验Source；C-A检验repair；D-C检验强repair下Source；D-E/F检验多版本价值。所有结果均要计量选择开销，不能只呈现离线oracle。

### P4：实际早层执行、10段场景与性能

固定d2的真实执行重新跑质量。若mask可在block3 attention前提交，first reuse=3；若实际只能更晚，精确记录并重做同边界对照。不能继承第9层结果。

先单目标，再A-only/B-only/A+B，再真实多chunk（2/5/10档按数据与长度清单）。特别加入前九段复用、C10 full场景，报告C10出生类型和G。Source capture开/关配对检查不改变当前答案。

保留两套比较：同边界/同驻留的执行匹配诊断；各方法正常策略的系统比较。不得强迫CFO/单Source支付其不需要的d2探测。CPU/SSD全量Artifact并非候选评分必需；它只服务winner执行。

15%质量成立后，只在fit上测试12%、10%，再冻结到held-out。少算token不等于少传未修复KV，实际TTFT是主结果。

GPU warm、pinned CPU、SSD声明页缓存状态分别报告；建议每个条件3次预热、5次测时，平衡方法顺序。它们不是独立QA样本。按组/请求先汇总重复，避免把重复计时当流量。

### P5：两个来源策略的自然生命周期对照

固定同一输入序列、同一选择/repair策略和相同总字节预算：

- `EXACT_ONLY`：只入G0，遇到混合候选就丢弃，不强迫整请求重算。
- `ALLOW_MIXED_G1`：允许G0/G1，G2/UNKNOWN拒绝。

各K=1/2/4独立空池或独立合法warm快照，同一总上限，不给mixed另外加4个槽。两策略因历史决策产生不同池属于正常，但记录全部因果事件。

自然运行不预装未来E/M对，不强制制造mixed为提高命中；paired诊断与真实增长分开。最后一个请求capture/发布/清理纳入总服务完成端点。来源控制增加元数据，不允许父KV引用阻止GC。

若mixed供给增长但质量或同字节总体性能变差，H4/H5失败；不能只宣传创建率。若G1上限使后续供给受限，报告，不自动开放G2。

### P6：正式冻结与相关工作

两模型使用内容/来源隔离的fit与held-out；规划每模型20个隔离组、约300请求只是目标，不是1%风险认证。输入规模依方差、组相关和实际资源在看输出前冻结。

至少CacheBlend执行基线、Cache-Craft/CFO、强单Source和一个可运行的近年query-aware方法；KVCOMM等语义/状态适配是必查近邻。作者原生、同后端复现、inspired、reported-only分开，不能把论文不同硬件数字拼成胜负表。[R1–R4]

投稿前更新逐机制新颖性表，不承诺全球绝不重复。若仅repair有价值，移除Source贡献；若只有exact有效，明确缩小来源结论；若系统不加速，不称加速系统。期刊分区不写入技术PASS标准。

## 11. 指标、统计与停止条件

### 11.1 四种阶段结果

- `PASS`：指定范围下满足预登记晋级规则，仅允许下一阶段。
- `FAIL`：输入/测量有效，但指定效果或安全要求未达到。
- `INCONCLUSIVE`：组数、精度、标签或对照不足，不能当成功或普遍失败。
- `BLOCKED`：环境、授权、数据或正确性缺项阻止执行。

### 11.2 质量

P1继承逐请求F1容忍`F>=F_dense-0.02`；同时报告绝对F1/EM、token输出、失败率。dense错误时相对合格不等于正确。

mixed新增风险：配对M1-vs-E与M1-vs-dense均报告；推荐正式mean F1非劣界0.01，采用预登记的配对、依赖组重采样单侧区间。高损失/事实冲突病例单独列，不仅报告均值。

浅层一致、旧新KV差异、G值、支持句mask覆盖是机制指标，不是替代质量。online决策不读标准答案，不用离线dense答案决定是否回退。

### 11.3 时间、成本、容量

`TTFT=t_first_token-t_arrival`，包含队列。prefill/decode/e2e/capture/维护另列。CUDA Events只解释GPU组件，跨流有事件依赖；重叠区间求并集，不将并发copy与compute相加成总时间。

保留source-state读、K比较、QK评分、winnerV、TopK、mask_ready、主等待、每层copy/compute、target full token-layer、captureD2H、共享manifest写、shadow bytes、peak staging等。

首token后维护不影响该请求TTFT时，也影响总服务成本与后续排队；不能隐去。离线S0建设与历史Source建设都报告，不把一方离线成本塞进warm时延而免去另一方。

同质量下中位TTFT改善10%、P95恶化不超过5%作为本任务的预登记工程目标，预登记工作负载内评价，不是性能承诺或发表门槛。固定比例选更好Source主要先改变质量，若实际工作量没变，不自动声称速度收益。

### 11.4 完整请求成本模型缺失时

当前在线原有0.8成本准入若保留，必须使用匹配本策略/来源类型/执行mask的实测Profile；不复用旧表伪装。旧5%选择时间上限仅保留为历史模式，不重新强加于新end_to_end_aware。[C7]

未知成本返回UNSUPPORTED/明确回退，不填0。成本模型预计通过不是实际永不超时的保证。

### 11.5 统计与过拟合控制

报告request-weighted与macro-group；建议配对cluster bootstrap 10000次并冻结种子。两个组不足以支撑广泛泛化；只报告pilot。多个主对比预声明顺序检验或校正，探索图不能临时升级主要终点。

失败/超时保留分母，按冻结规则F1=0并另报成功子集；不得删掉最慢和失败请求。目标准则只在本轮新输出前修改一次并记录依据，此后不追结果。

## 13. GPU授权、预算与恢复

每阶段生成精确动作清单（模型/目标/出生来源/repair/boundary/cache/重复），列出目标推理、Source构建、额外dense对照和数值检查各自数量。P1消费动作上限分别为180、36、72，不代表所有动作总成本；建设动作必须另有界。

剩余额度不足完成下一动作及清理时停止。仅释放本任务资源；销毁整个实例需单独既有授权。网络失败、缺模型、OOM不擅换模型或降精度。

恢复键至少包含：runtime/patch/worktree/model/tokenizer/input/sourceArtifact/poolSnapshot/sourceType/G/执行manifest/provenancePolicy/selector/repair/producer-consumer/decoder/cacheCondition/seed-repetition。不同来源即使prefix token相同也不能复用同一个结果。

原子结果+checksum校验后再标完成；模拟输出、CPU演示或缺字段动作不能当真实GPU成功。

## 15. 必须保留的失败路线

- H1无空间：停止扩展多Source；保留执行器和负结果。不自行改成另一论文主线。
- H2无增量、H3有效：如实说明贡献在repair，不声称新版本选择有效。
- H4混合来源不合格：暂停mixed发布/使用的默认化，继续有证据的exact对照；不能说放宽策略已被验证。
- 浅层签名碰撞使风险不可辨：先报告，再决定有界调整观察或拒绝；不自动增加中层probe。
- H5成本为负：不写成加速系统；先看必要成本下界，没余量不投入复杂kernel。
- 任一正确性/权限/来源未知：BLOCKED或失败封闭，不关闭检查追结果。
