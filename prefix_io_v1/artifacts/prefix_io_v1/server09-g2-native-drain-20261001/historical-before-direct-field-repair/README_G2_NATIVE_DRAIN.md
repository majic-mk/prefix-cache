# Independent native drain CPU candidate

This append-new module supplies the missing scalar conversion after original handler shutdown. It does not install a hook or execute a cache engine/model. Default off returns through the original shutdown immediately. Enabled CPU observation keeps the exact original call, return identity and exception priority, then consumes one original snapshot only after successful shutdown and source-bound unchanged method identities. Observer faults invalidate observation without skipping or rerunning the original call.

The original snapshot has no worker_joined or observation_failures member. Worker closure is checked using the locked normal Handler -> Coordinator -> IoReactor shutdown source (which calls join with wait=True) plus actual reactor._worker.is_alive() equal to bool False. Actual reactor._observation_failures is read separately. Sixteen native owner collections/counts, handler active jobs, valid parent admission, four-stage accounting and Linux AIO state must all close. Acceptance equals completion only when actual transferred bytes match and failed/inflight counts are zero; Linux AIO accepted/completed/reaped must agree and unresolved/unreaped queues must be empty. Future.done is not used by the provider and cannot establish drain. The observer does not clear owners, close, join, synchronize or submit I/O.

Tests run exact locked original shutdown/snapshot ASTs and original StageAccounting methods with explicit CPU fake worker/OS/backend objects. The native package and torch/vLLM are not imported. A real native/CUDA handler has not been constructed or drained. The immutable receipt and same private frozen DrainEvidence class contain copied scalars, keep no runtime owners and never confer GPU/production/effect qualification. Successful tail conversion cannot be called before or after its original-shutdown observation window.

See G2_NATIVE_DRAIN_CPU_PLAN.json for six source refs, exact method AST refs, field mapping, API, command and remaining qualifications. LOCAL_CPU_DRAIN_TEST_RESULT.json records actual local execution. Root can replay the test with its existing .venv/bin/python -B -I -S and explicit --source-root pointing to the original project root. Keep frozen collector and runtime_connector sibling directories unchanged. A new native G2 run requires a separately frozen scope and new explicit GPU authorization/reservation; this module cannot launch it.
