# Independent combined C5 runtime CPU review

This review checks the new normal-entry source composition against the frozen
Stage C common candidate and Stage A notification adapter. It never changes an
ancestor, imports a real model, constructs a native cost receipt, starts a GPU
job, or replays the completed 132-trial scored CPU experiment.

The canonical receipt, policy and bridge must resolve from the same Stage C
overlay. The notification adapter must remain byte-identical to Stage A. A new
launcher must point to the Stage C collector and runtime-identity helper, keep
the owner LABEL separate from frontend request ID, install the notification
helper only through the existing call site, and retain early native blocks.
Old GPU UUID, storage template, permission file and ancestor authorization must
not become active in the new composition.

Dynamic positive checks are confined to the actual collector.install API with
origin=cpu_fixture and the shared helper's uninstalled off/shadow cleanup.
Connector, worker and Event classes are declared synthetic. The queue is an
exact queue.Queue instance. Original source-extracted wait methods are used
only as an interface fixture, never as evidence of native I/O or model execution.

No receipt or RuntimeSingleFileIdentity is fabricated. No private bridge fields
are changed to manufacture a native attachment. The unchanged native bridge,
reactor installer and on helper must reject this CPU fixture. Positive on
integration remains source-audited only; its four invalidation hooks, queue
observation and original drain ordering are preserved, not CPU-qualified.

All result fields for GPU/native/full-runtime/cost qualification stay false,
and effective costs, valid receipts and GPU UUID stay null. Resource qualification
is separate. In the current half-core cgroup a preflight must report the actual
resource block, without a formal benchmark or a change to the frozen thresholds.

The source-locked runner closes explicit review/launcher dependencies and the
actual Stage C candidate Python tree, verifies every outer source row before
and after, reports actual failure/error/skip counts, and refuses model imports.
