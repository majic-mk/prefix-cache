## What CPU integration actually exercises

The 23 new targeted tests execute the actual C5 `collector.install` with
`origin=cpu_fixture`, explicit synthetic worker/connector/events and four real
bound Python invalidation methods. They execute the actual normal helper for
off/shadow, original exact `queue.Queue`, original prepare delegation/restoration,
original source-compiled `_drain_incoming` / `_intake`, old wake disposal and
original STOP intake. The full reactor class AST is compiled from the unchanged
C5 source; no second reactor algorithm is written. No physical backend, model,
Torch, vLLM, native I/O, native CUDA Event or measured performance path runs.

Positive on-mode installation is deliberately **not** claimed. CPU origin makes
the real `current_single_file_step` return unknown. The real original bridge
refuses missing native identity/receipt; the real helper refuses an unbound
capture; the original reactor refuses waiting without an active native receipt.
Tests verify those refusals, keep capture origin unchanged, leave all bridge
weakrefs unchanged and fabricate no native-typed receipt or costs. Thus
`actual_on_installed`, `actual_native_bridge_attachment`,
`full_entry_cpu_cost_measured`, `full_runtime_cost_qualified` and
`on_observation_cost_measured` are all false. Effective cost, budget and native
receipt remain null. Positive on callsites are source-audited only.

This intentionally differs from the earlier Stage A positive helper unit
fixtures. Those fixtures already used explicit synthetic private bridge metadata
and cannot supply honest native integration coverage for this combined version.
They are not rerun or promoted here. Likewise the old 132-trial benchmark is
immutable, already resource limited, and does not measure this complete entry.
Its `RecordedQueue` subclass and manually assembled observer cannot invoke the
normal exact-Queue helper unchanged. The original CPU comparison's schedule,
thresholds and cgroup rules remain historical evidence; no new score or adaptive
rerun is performed by this preparation.

The initial local 23-case development run had 22 passes and one error: the
fixture omitted the actual normal launcher's common-candidate import path, so
the bridge could not import `single_file_runtime_binding`. Adding precisely
that original search path allowed the real identity refusal to execute. No
native condition/type/origin check, bridge source or existing evidence was
changed to make it pass. This was a local CPU fixture error, not a GPU attempt.
