# Development runtime wiring V4

This directory contains executable CPU/guarded-runtime wiring, not only a proposal. It adds a scoped development U/off or I/shadow consumer with no external service SLO/deadline, while keeping the original author engine, original GPU guard, original private calibration issuer, current-arm/closed-peer namespace checks, complete frontend/CUDA capture and original shutdown/OS closure.

Current actual frozen I policy has internal_step_budget_ns=null. **U/off does not need an I preview budget. I/shadow is explicitly UNBOUND until a real positive engineering preview setting is selected on development data and frozen in the actual pair.** No number is supplied by this code. Such a setting remains observation-only and cannot qualify an ordinary I action, formal native reserve, service SLO or effect result.

## Common fixes and development-only dispatch

Common source provenance fixes in V4 are separate from development semantics: runner.load executes the exact checked source bytes and rechecks after execution; all private formal F instances now use a source-only pure helper loader with original byte pins, import boundary and before/after closure. Existing valid pyc files are ignored and retained. New private module names use a sequence as well as a clock reading, so repeated clock readings cannot alias a previous module. Effect validation functions, SLO/native-reserve conditions and actual private issuer remain the original ones.

The development-only adapter has separate descriptor/result schemas. It derives the exact source-pinned original F input function, removing only the nine external deadline/authority statements while retaining the other 34 statements, original full replay and actual namespace callback. Its scoped activation derives original leaf/calibration/private-package checks with no external deadline and reuses the unchanged issue object. Phase preflight repeats the real binding plus actual activation/pair/calibration/guard replay; forged gate flags or preview values cannot substitute. Development engineering budget fields/origin are exact, no service safety/reserve claim is allowed, and the current null I setting rejects shadow.

Effect/evaluation rejects a development descriptor and retains original F/activation/phase/private-issuer/native-reserve behavior. The ordinary on branch cannot enter the development adapter. Legacy qualification workload/phase functions, original drive_original_engine and verify_guard retain their exact AST. The entire runtime execute.finally and original effect/native capture/peer/reserve/controller helpers also retain their V3 AST.
