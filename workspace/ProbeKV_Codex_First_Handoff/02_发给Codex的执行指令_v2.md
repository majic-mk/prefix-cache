## 二、研究路线固定

- 多历史 Source，按精确 Segment 身份维护少量版本；单 Source 必须保留为强对照。
- 当前请求浅层 K-only 选择 Source；K+V 选择作为消融。
- Source freeze 后，以 **Query 关注度 × winner 的 K/KV 偏差** 选择 repair token，不能简化为纯 Query。
- 保留原 CacheBlend 逐层执行基础。先固定 15% repair，证据支持后再研究较低比例。
- 不改成单 Source 主线、联合 Source–mask 搜索、QCFuse anchors、CF-Repair、学习型选择器或额外深层 probe。

## 三、来源与存储要求

- 目标 Segment 的全部 token、全部层连续完整重算，才具备完整片段候选资格；上游允许近似复用，不强制前面所有 Segment 重算。
- 区分 `EXACT_CONTEXT` 与 `MIXED_CONTEXT_FULL_SEGMENT`；禁止把混合来源标成旧 `DENSE_EXACT`。
- 持久池初期只允许任务书定义的 G≤1，UNKNOWN 来源不发布。完整计算不能洗掉已有近似依赖，普通同请求传播也不能每层或每段加一。
- 完整重算只使其成为候选，不保证必定入库；仍需满足触发、去重、预算、容量及原子发布要求。r=1 由全层实际执行账本证明。
- Source 只保存目标片段 KV、轻量选择状态和元数据。前文及执行配方使用共享 manifest 引用，不复制前文 KV，不以 tensor view 或父租约间接保留整请求。
- Source capture 与整请求 Prefix shadow 解耦，默认收集 Source 不创建整请求 shadow；混合来源不进入精确 Prefix Cache。
- 只导出正常执行已产生的结果，不为填满 Source 池暗中额外前向。诊断 dense 与自然在线缓存池隔离，成本单列。
