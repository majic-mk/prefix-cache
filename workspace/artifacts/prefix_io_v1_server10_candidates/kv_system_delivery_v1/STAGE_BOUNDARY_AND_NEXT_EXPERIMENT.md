# 新服务器系统验证的阶段边界与下一实验

本交接截至 2026-10-03；KV02 及修复版作业的最终状态等待 root 核验实际 receipt，不预填通过。

## 本轮可以得出的结论

新服务器六次基础 GPU 验证已通过，覆盖参考请求、原生 CUDA/AIO off/shadow 和正常模型冷/重复请求各完整生成 128 tokens。这说明现有执行器和缓存基础路径可以在本机运行，不等于 P4 完成或方法已有提升。

第 7 次 `populate01` 的真实生产 KV 字节采集通过并完成 shutdown，但末端 CPU 请求映射将 `0` 与 `0-hex8` 判为不匹配，child 退出码为 78。因此该作业整体仍记失败，原始证据保留。修复版拟使用 v2 的两个有限新作业；本文件不将待运行或待核验作业计为成功。

只有 populate 与 fresh-paired 的实际字节、请求对应、来源和生命周期回执均通过，才能补齐本次有限 T05 资格：同一份模型生产 KV 从 canonical GPU 页经 D2H、持久文件、实际读取、H2D 到模型使用前的逻辑字节一致。范围仅限实际采集的前缀、布局和作业；不是独立 BF16 重算的一致性，也不是所有负载的证明。采集增加 CPU 拷贝和同步，其时延不能用于性能或成本标定。

## 历史 P3 与未完成的 P4

旧 P3 的有限 pilot 闭合结论保持不变：在其冻结开发负载上，U 的中位 cohort 时长优于 F16、P4、F8、P512；没有证明新增策略收益。每臂两次仅支持当时的描述性比较，不代表全局最优。这里的 P4 是压力基线候选名称，与实施阶段 P4 不同。新机资格不会改写这些结果，也不要求重做已经完成的全部 CPU 工作。

新机尚需有效成本、持续 decode 干扰与目标资源等待的证据。正常输出及 off/shadow 通过，仍不能替代完整 step/output/drain、GPU/host 时钟关联和 actual load 的采集资格；已有 G2 报告的 `GPU_collector_verified=false` 必须保留。

实施阶段 P4 还需生产成本/ETA 的有效范围、真实释放条件，以及主动 D/I/J 模式的 mandatory 进展、额度与生命周期安全、关闭回退和同执行器小对照。没有真实 release witness 时保持未知与回退，不授予提前物理释放信用。T05 字节证明不能替代这些门槛。

## 确切下一实验

完成上述 KV 回执判定后，优先使用现有 V2 raw-pair 流程，在当前机器、同一 Qwen 模型、固定实际 batch/context 下，执行完整 128-token decode 的无 I/O（A）与合法 SSD-only preload（B）ABBA 小配对。

运行前须满足以下实质条件：

- 完整 step 与实际逐 token 输出接点可核验；只测 `model_forward` 不冒充完整 decode step，scheduled work 不冒充实际执行负载。
- 固定可复现的请求与前缀条件、实际 KV/staging 预算、预加载和复制合并条件；保持原 LoadPlanner 唯一准入、原异步执行器及统一停止规则。
- SSD-only preload 确实进入声明的独立测量窗口，记录真实字节、GPU event、host/owner 时间和完整 accepted-I/O 排空；自然耦合 D2H→write 不拆成伪单阶段 cell。
- 关闭本轮完整字节采集等诊断性同步；使用未消费的有限作业范围，沿用现有 GPU 累计预算及存储下限。

该实验首先验收采集来源和一个合法条件成本，不直接宣称总体吞吐提升。通过后，再在共同固定额度下进行 C00/C01/C10/C11 并保留独立 U 的小 pilot；相关成本、负载或释放条件未资格时，对应研究策略继续回退。正式收益结论仍需正常持续请求流、最强可比基线和独立评估。

依据：交接包 03 的 P3/P4、T05 和工程/研究门槛，04 的唯一准入与持续 decode 要求；历史 P3 最终证据、P4-02 runbook 和本机六次基础系统报告。本文件为阶段解释，不替代原始作业 receipt、源锁或预算账本。
