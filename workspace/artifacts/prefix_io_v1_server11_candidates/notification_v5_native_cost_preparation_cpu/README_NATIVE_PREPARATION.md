# C5 native common-cost code: CPU preparation only

This new incremental copy prepares the author-route native six-window collector,
raw reserialization, original numerical verifier and canonical receipt binding.
It has **not** run a GPU, model, physical native I/O, real CUDA Event, or native
receipt issuance. No effective cost or strategy budget is available. P4 and
performance improvements remain unverified.

The `common_candidate` tree copies the frozen C5 Python files. Only its
`prefix_io_control.p4_single_file_receipt` is replaced in this new tree. The
reactor, full 128-frame collector, policy, bridge, original formula and resource
ownership bytes are unchanged. `SOURCE_INHERITANCE.json` records every parent
Python file and its original SHA-256. Copied old tests remain ancestry sources;
they are not rerun as new qualification or interpreted as valid C5 issuance.
`initialize_sources.py` is the one-time append-only copy/adaptation provenance
tool. It refuses existing destinations. Final adaptation is the source now in
this directory, and the final SHA pins in the canonical receipt are authoritative
under the new CPU source lock; do not reinitialize a frozen copy.

The adapted real calibrator preserves six fresh original processes, AB/BA/AB,
two calibration pairs plus one independent heldout pair, 129 prompt / 128 cached
/ 128 complete output tokens, offset 16, one 917,504-byte SSD read and eight
accepted parents. Common calibration uses `bridge=None`: it does not measure
the on-only notification or Queue observation. The legacy collector lookup is a
local alias of the actual new C5 source ref, and the adapter before/after SHA
and all 128 frames remain required. Common calibration capture run_id is the
external request ID while the journal run is the job label; runtime on-mode
capture identity differs and must not be blindly reused.

All native launcher, configuration, guard, plan creation and public native
receipt issuance functions immediately raise
`GPU_BLOCKED_C5_NATIVE_COST_CODE_PREPARATION_ONLY` before accessing configuration,
budget, model imports or GPU paths. All CLIs return the blocked document and
exit 2. GPU UUID, permission, physical storage template, GPU source lock and GPU
ancestor authority remain unresolved (`None`). Historical source ancestors are
only code provenance, never permission, valid GPU costs or a new authorized job.
No config, effective GPU plan, scope, job or budget reservation is created.

CPU raw reserialization must explicitly pass `synthetic_cpu=True` (exact bool),
use `cpu_preparation_only=True`, `evidence_origin=synthetic_cpu_contract`, the new
C5 job/source/collector references and UUID None. The original raw shape checker
still requires legacy `native_gpu_recording` vocabulary inside fabricated raw
fixtures. The enclosing input and all returned results are explicitly synthetic
and cannot issue a native grant. `audit_synthetic_raw` reads six synthetic raw
files, reruns the exact original formula/causality/lifecycle checks, and returns
no effective cost or budget, even when the synthetic heldout sample is covered.
No constructor, result dict or PASS string bypass is added. The canonical
`ExactSingleFileReceipt` type is the one imported by the unchanged exact-type
policy check, and the bridge uses that same policy module. Hash pins detect
drift and are not signatures or a security boundary against arbitrary Python.

`run_cpu_native_preparation.py` runs only the 30 new targeted counterexamples,
not previous CPU qualification or synthetic performance benchmarks. It verifies
all supplied locked files before and after, forbids torch/vLLM/native backend
imports, records zero GPU/model processes and all qualification fields false.
Temporary synthetic raw files are bounded per fixture, created under private
temporary directories and cleaned by the test fixture. They are not archived as
experimental data. Source ancestry and numerical AST checks read old frozen
sources without changing them.

Server command (the parent records exact arguments and actual stdout/exit):

```text
.venv/bin/python -B -I -S <stage>/run_cpu_native_preparation.py \
  --project-root <project> --source-lock <new CPU source lock> \
  --output-dir <new stage>/SERVER_CPU_01 --location server_cpu
```

Optional `--candidate-root`, `--native-root` and `--original-estimator` provide
actual old frozen source locations for local replay; server defaults resolve the
current project C5, native_v6 and original estimator sources. Every actual
dependency must be in the parent source lock. The root delivers the server CPU
logs, source lock, bounded archive and SHA verification separately.

Local development failures are preserved in `LOCAL_DEVELOPMENT_RECORD.json`:
the first 30-case run had two failures and one error (incorrect rejection text,
missing mandatory P4Config constructor arguments, controller CLI did not propagate
its blocked return code). The next had one test failure because the unchanged
bridge validates the exact policy type rather than importing the receipt class
directly. Tests now check the real module/type relation; no engine or policy
changes were made to satisfy these checks. These are local CPU source/test fixes,
not failed or successful GPU runs.

Actual GPU qualification still needs a real allowed GPU UUID and a newly
authorized source/job/budget binding, real C5 six-window raw evidence and native
issuance, unthrottled complete-entry CPU cost qualification, then original
off→shadow→on lifecycle and on-only observation/cost coverage. This CPU version
intentionally cannot unblock any of those gates. If the original policy issues
without a real deferral, later experiments must report NOT_EXERCISED; changing
workload, margins, budget, thresholds or sampled windows to manufacture waiting
is outside this preparation.
